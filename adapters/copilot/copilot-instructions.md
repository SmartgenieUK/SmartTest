# SmartTest instructions

Use DevGenie's SmartTest discipline for material software changes.

- Read `skills/test-plan/SKILL.md` before deriving tests from a requirement.
- Read `skills/test-impact/SKILL.md` when selecting blast-radius and regression checks for a change.
- Read `skills/test-review/SKILL.md` when reviewing whether tests and evidence are adequate.
- Read `skills/debug-causal/SKILL.md` for non-trivial defect diagnosis; do not claim a proven root cause unless its proof gate is satisfied.
- Inspect authoritative repository requirements and existing tests before proposing new ones.
- Treat coverage, test counts, and green checks as evidence inputs, not proof of correctness.
- Record verification evidence, missing evidence, explicit N/A decisions, waivers, and residual uncertainty.
- Keep verification proportionate to risk and avoid unrelated implementation scope.
